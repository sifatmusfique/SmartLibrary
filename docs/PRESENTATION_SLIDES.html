Core Design

Four Custom Data Structures

1. BookCatalogue (Bounded Array)

Raw Book* array (default 100). Maintains dense prefix [0, count) with left-shift deletion in O(n) and O(1) append.

2. HistoryList (Singly Linked List)

head + tail pointers for O(1) chronological append, monotonic 64-bit TxIDs, and safe node deletion.

3. ReturnStack (Bounded Array Stack)

LIFO int* stack tracking recently returned IDs in O(1) with strict overflow/underflow checks.

4. RequestQueue (Circular Array Queue)

FIFO circular buffer using (front + count) % capacity to reuse slots in O(1) without shifting.

System Architecture

Layered Design & Failure Atomicity

  • UI Layer: ConsoleUI (whole-line safe parsing, Menu 0–15) + optional smartlibrary_gui loopback server sharing the identical engine.
  • Coordinator: LibraryManager enforces consistency — blocks deleting borrowed/pending books and prevents return when stack is full.
  • Failure Atomicity: Pre-allocates HistoryList::PendingNode before mutating catalogue, stack, or queue; failed allocations leave state untouched.
  • Educational Maintenance: Submenu 14 inspects/edits historical logs and stack/queue offsets without altering live availability.

Live Demonstration

Demo Flow (Console & Live Web Dashboard)

  1. Add Book 101 (Data Structures / Seymour Lipschutz) & Search 101.
  2. Borrow 101 (Available → Borrowed, Tx#1 appended to HistoryList).
  3. Borrow 101 again → Enqueued in Circular RequestQueue.
  4. Return 101 → Pushed to ReturnStack (top = 101), Tx#2 appended.
  5. Process FIFO Head → Dequeues 101, re-borrows, Tx#3 appended.
  6. Edge cases: Pop empty stack (Stack Underflow!) & Search 999 (Book not found.).
