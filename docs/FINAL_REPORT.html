1. Objective & Problem Statement

A library management workflow requires distinct operational guarantees across four domains: (1) a fixed-capacity inventory supporting fast lookup and contiguous iteration, (2) a chronological transaction audit trail that grows dynamically without element shifting, (3) a recently returned books desk following Last-In, First-Out (LIFO) order, and (4) a fair waiting request line following First-In, First-Out (FIFO) order when books are unavailable.

Per the official CSE 2103 rubric, all core structures are implemented manually in C++17 without ready-made STL container substitutes (std::vector, std::list, std::stack, std::queue, std::map, std::set) or <algorithm> helpers. Each structure implements insert, delete, search, update, and traversal along with empty, full, overflow, underflow, duplicate, and not-found handling.

2. Data Structures Selection & Alternatives

Module Chosen Structure Alternatives Considered Justification
BookCatalogue Bounded Raw Array (Book*) Linked List, BST, Hash Table Contiguous memory layout for bounded inventory (default 100), direct index inspection, and explicit left-shift deletion invariant [0, count).
HistoryList Singly Linked List (head & tail) Dynamic Array, Doubly Linked List O(1) chronological tail append without array resizing or shifting; tracks monotonic 64-bit transaction IDs and supports safe head/middle/tail deletion.
ReturnStack Bounded Array Stack (int*) Linked Stack Zero per-push heap allocation, O(1) LIFO push/pop, explicit stack overflow/underflow demonstration, and top-relative offset search/update.
RequestQueue Circular Array Queue (int*) Linear Array Queue, Linked Queue Reuses vacated front slots in O(1) via (front + count) % capacity. Tracking count distinguishes full vs. empty cleanly even at capacity = 1.

5. Implementation & Failure Atomicity

  • Modules: Book.hpp, BookCatalogue.{hpp,cpp}, HistoryList.{hpp,cpp}, ReturnStack.{hpp,cpp}, RequestQueue.{hpp,cpp}, LibraryManager.{hpp,cpp}, ConsoleUI.{hpp,cpp}, and optional GUI adapter JsonApiAdapter.{hpp,cpp} + HttpServer.{hpp,cpp}.
  • Failure Atomicity: borrowBook, returnBook, and processNextRequest pre-allocate a HistoryList::PendingNode before mutating catalogue status, stack, or queue, committing the node via noexcept linkage only after preconditions pass.
  • Input Hardening: ConsoleUI parses whole lines via std::getline and strict integer conversion, preventing infinite loops on malformed input, integer overflow, or EOF.
