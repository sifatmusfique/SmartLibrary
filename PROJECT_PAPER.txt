                 Smart Library Management System
Project Title: Smart Library Management System Using Array, Linked List, Stack and Queue.
Objective:
• To develop a console-based library system using core data structures in C++.
• To manage books through an array.
• To maintain borrow/return history using a singly linked list.
• To keep recently returned books using a stack.
• To manage waiting borrow requests using a queue.
• To demonstrate insertion, deletion, searching, updating, traversal, overflow, underflow and not-found handling.
• To analyze the time and space complexity of the implemented operations.
 Problem Statement
A library needs a simple system to store book information, search books, add or delete books, borrow and return books, maintain transaction history, and handle waiting requests when a book is unavailable. A single data structure is not equally suitable for all of these tasks. Therefore, the project combines an array, linked list, stack and queue so that each operation follows an appropriate data-structure model. The project follows the course requirement that the core structures are implemented by the group instead of using ready-made STL containers. The supplied project guideline specifically requires data-structure-based projects, implementation of the core structures, main operations, edge-case handling and complexity analysis.
Data Structures Used and Justification :
Array — Book Catalogue
An array stores the main book records in contiguous memory. It is simple and suitable for a bounded catalogue. It supports traversal and direct index access efficiently.
Singly Linked List — Borrow/Return History
A linked list is suitable for a growing transaction history because a new record can be inserted without shifting existing records. Each node stores book ID, title, action and a pointer to the next node.
Stack — Recently Returned Books
A stack follows LIFO (Last In, First Out). The most recently returned book is kept at the top, so push and pop naturally represent recent-return operations.
Circular Queue — Waiting Borrow Requests
A queue follows FIFO (First In, First Out). Borrow requests are processed in the order they were received. A circular array queue uses memory efficiently and demonstrates overflow and underflow handling. These structures directly match the project requirement to use one or more core data structures and justify their selection. 
Main Operations

         • Add/Insert Book
         • Delete Book
         • Search Book
         • Update status
         • Traverse/Display all books
Linked List:
         • Insert history node
         • Traverse history
         • Handle empty history
Stack:
         • Push returned-book ID
         • Pop recent return
         • Display stack
         • Stack overflow/underflow
Queue:
         • Enqueue waiting request
         • Dequeue/process request
     • Display/track pending requests
     • Queue overflow/underflow
The system also handles book-not-found cases and a full catalogue. These edge cases are included because the project guideline requires operations and handling of empty, full, overflow/underflow and not-found conditions.

 Advantages
• Demonstrates four important data structures in one practical application.
• Easy to operate through a menu-driven interface.
• Clearly separates each data structure according to its purpose.
• Includes edge-case handling.
• Suitable for live demonstration and viva.
• Can be extended with student accounts, fine calculation, login, file storage and a GUI.
Current limitations:
• Data is stored in memory and is lost when the program closes.
• The catalogue has a fixed maximum size.
• The interface is console-based.
Future improvements:
• Add file handling or a database for permanent storage.
• Add student/member records.
• Add due dates and fine calculation.
• Add login and role-based access.
• Add a GUI.
• Add sorting by title, author or ID.
• Add more advanced structures such as BST or hash table for faster searching.
The project guideline notes that GUI is optional but appreciated, so a GUI can be added as a bonus improvement.
Conclusion
The Smart Library Management System demonstrates how different data structures can be combined to solve a real-life problem. The array manages the main book catalogue, the linked list stores transaction history, the stack handles recent returns, and the queue manages waiting requests. The project therefore demonstrates both practical application and algorithmic understanding. The implementation follows the supplied CSE 2103 project requirements for a data-structure-oriented solution, custom core structures, operations, edge-case handling, complexity analysis, system design, testing and conclusion.
